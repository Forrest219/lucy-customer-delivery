# r6 验收说明

当前为升级验证候选，以下项目尚需原生 amd64 环境实际执行并留证。仓库根目录旧版 `验收命令.sh` 针对 20261009-v1，包含旧镜像与匿名管理 API 假设，不作为 r6 验收入口。

以私有实例目录中的 `package/ACCEPTANCE.md` 和 `package/UPGRADE-RELEASE-CHECKLIST.md` 为完整验收清单，记录每项 PASS、FAIL 或待验，不以脚本退出成功替代整体验收。

- 原 PVC UID、资源名称、内容根和外部端口保留，运行镜像身份属于本批次候选。
- 初始完整备份、原 values、原镜像/revision 和恢复记录存在，备份哈希通过。
- 正确密钥创建首个所有者；缺失/错误密钥和重复认领被拒绝。
- 退出后可重登，未登录访问受保护管理 API 被拒绝；重启后仍可登录，不重新认领。
- 原连接、语义层、业务 Wiki、业务 Skill、权限、历史审计按预期保留。
- 原 MCP Token 可完成初始化、工具列表与一条真实允许查询，无 Token 与原禁止查询仍拒绝。
- 在同类测试环境完成旧版本与初始 PVC 的完整恢复，再次升级通过。

包内 `package/scripts/acceptance.sh` 提供部署后基础检查（默认包含连接测试和强制索引重建，会更新索引，不属于升级前只读检查），供应方填入实际资源名、URL、连接及内容根后使用。MCP Token 通过受限文件或环境变量传入；基础脚本不能替代管理员旅程、权限查询和恢复演练。认证后的管理 API 检查由有权限的管理员在受限会话下完成，不把 Cookie 或 Token 回传到报告。

回传软件包 SHA256、实际镜像 imageID、前后资源 UID、Helm revision、工具版本、时间与逐项脱敏结果；不回传完整 values、Secret、凭据或 PVC 备份。客户正式升级前须由供应方完成放行复核。
