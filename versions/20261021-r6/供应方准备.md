# r6 供应方准备与检查补充

本批次目前只用于供应方原生升级验证。正式客户交付前，先完成本批次实际升级与恢复验收，再准备真实客户实例。

## 配齐私有实例目录

1. 软件包从本批次 Release Assets 或供应方受限渠道取得，校验外层和包内 SHA256；确认元数据属于 r6，软件目录保持完整。
2. 供应方核对逻辑实例归属，提供绑定本包的私有附件。该附件包含密钥、签发状态、元数据与 `scripts/prepare.sh`，不上传本公开仓库；同实例复用原密钥，另一实例另行签发。
3. 按 [实例示例](instance.upgrade.example.json) 填写实际 context、namespace/release/Deployment/Service/PVC、UID、旧镜像、访问地址与节点导入映射，并核实旧系统无管理员。示例值不能直接部署；实例 ID 与签发状态由附件自动注入。
4. 按[恢复模板](恢复说明.md)填写 `RECOVERY.md`，确认旧镜像、原 revision、备份空间、受限另存位置及负责人。HTTPS 使用实际 TLS 和所需 CA。
5. 在 Git、inbox、缓存和构建上下文之外，使用附件入口准备全新的实例目录；私有目录 0700、普通文件及私有归档 0600。不要混入旧包目录或修改原密钥。

```bash
umask 077
bash "$ATTACHMENT/scripts/prepare.sh" \
  --package "$SOFTWARE_ARCHIVE" --config "$SITE_CONFIG" --output "$NEW_INSTANCE_DIR"
```

供应方应配齐可执行的私有交付目录和实际路径说明，客户无需编写 values 或生成密钥。

## 保留旧内容兼容检查

`scripts/deploy.sh --dry-run` 负责软件/实例身份、账号状态、Secret 引用、节点及候选渲染，不能替代全部旧内容兼容检查。

P09 还必须核对：Deployment 人工补丁漂移、实际语义资产的列类型、实际 `access.yaml` 的角色 AbsoluteDeny 工具冲突。按实际内容根执行；文件不存在、路径不明或解析失败不能按“零问题”通过。

对于旧平铺布局（`/data/lucy/semantic-layer` 和 `/data/lucy/webui/config/access.yaml`），可使用包内 `package/scripts/preflight-upgrade.sh` 的默认检查模式。它不修改 PVC 或应用 Deployment patch，但会临时向旧 Pod 的 `/tmp` 复制扫描程序并清理。检查时不传 `--apply-types` 或 `--apply-access`。

该脚本的渲染 values 必须与新入口将使用的合并结果一致。由供应方在受限目录通过包内 `customer-deployment-helper.py` 的 `deployment_values(instance, old_values)` 合并现场 `helm get values`，并设置该实例 `bootstrap.existingSecret`，保存为 0600 的 `preflight-values.json`；不能仅使用私有目录中的版本覆盖片段替代完整旧 values。当前 kubectl context 必须与实例相同。

然后执行，所有变量由供应方从实例配置填好：

```bash
bash "$INSTANCE_DIR/package/scripts/preflight-upgrade.sh" \
  --namespace "$NAMESPACE" --release "$RELEASE" --deployment "$DEPLOYMENT" \
  --chart "$INSTANCE_DIR/package/helm/lucy" \
  -f "$PRIVATE_PREFLIGHT_VALUES"
```

非平铺布局不能直接照用这个脚本的固定内容路径。供应方应使用包内同一 `preflight-upgrade-lib.mjs` 的 `scan-types`、`scan-access` 对实际路径只读扫描，并用 `preflight_upgrade_drift.py` 比较候选和现场 Deployment；记录真实路径与结果。不要把不匹配布局的空扫描记为通过。

发现问题先停止，由供应方确认修正与备份方案；处理后重跑兼容检查和 `deploy.sh --dry-run`。不得将检查单变成自动改写权限或语义资产的入口。

## 交付和放行

原生验证通过后，提供公开通用软件包/说明与面向该实例的私有附件、新实例目录、已填写恢复说明。客户按检查单完成所有适用项，复核后在维护窗口部署。

首次部署中的完整 PVC 备份、镜像导入和升级后验收仍在正式执行时完成。只读检查通过不代表已完成这些步骤。回传脱敏检查结果，不上传完整 values、私有签发记录、Secret、Cookie 或备份。
