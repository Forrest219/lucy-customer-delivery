# Lucy 2.0.0 r6 升级部署说明

适用：仍无管理员的旧系统，linux/amd64、单副本 Kubernetes/K3s，保留现有 PVC、配置和业务资产。升级包含停机备份和服务切换，请安排维护窗口。

> 升级验证候选，2026-10-21。r6 的原生升级与恢复验收待完成，目前不供客户正式升级。供应方应先按[供应方准备](供应方准备.md)配齐实例目录。本说明中的 `/opt/lucy-private/r6-instance` 由供应方在私有交付说明中替换为实际路径。

产品版本为 Lucy 2.0.0，随包 KTX 0.16.0、Chart 0.2.6。

软件包：`lucy-k8s-integration-delivery-20261021-r6.tar.gz`。

操作机需具备 Bash、Python 3.8+、kubectl、Helm，且当前 kubectl context 与交付实例一致。本离线入口使用 K3s/containerd 导入能力：按实例 profile，本机或映射 SSH 节点应可免交互执行 `sudo -n k3s ctr images import -`（K3s）或 `sudo -n ctr -n k8s.io images import -`（Kubernetes/containerd），映射覆盖全部可调度节点；不满足时请由供应方先确认部署方式。

供应方已准备实例目录时，按“升级前检查 → 正式部署 → 创建管理员”依次执行。若只收到通用软件包或缺少实例目录/私有附件，请联系供应方补齐。

## 第一步：完成升级前检查

先完成配套[《Lucy r6 升级前检查单》](升级前检查单.md)的 P01–P14，在部署机以正式升级使用的账号执行只读预检：

```bash
umask 077
cd /opt/lucy-private/r6-instance
bash scripts/deploy.sh --dry-run
```

命令退出码为 0 且最后输出 `status: DRY_RUN`，再由供应方复核其他现场检查项。全部适用内容 PASS 后，才能进入正式部署。任一项 FAIL 或待验，保持旧服务运行，处理后重检。

检查不会导入镜像、停止旧服务或执行 Helm 升级；正式备份、首次管理员和业务连续性在后续阶段验收。

## 第二步：正式部署

检查通过并进入维护窗口后，在同一实例目录单独执行：

```bash
bash scripts/deploy.sh
```

脚本自动核对软件和实例绑定、旧系统状态、原 PVC、Secret 引用及节点，导入镜像，停止旧服务并备份整个 PVC，然后配置引导 Secret、升级并检查镜像身份。预检只读；正式部署会短暂停止服务。

备份与原版本记录保存在该实例目录 `.deployment/`，其中包括 `baseline.json`、`baseline-values.json`、`initial-backup.json` 和 `backup-*.tgz`。请保留整个目录，并将备份另存到可靠的受限位置；这些文件可能包含客户数据和凭据。

预检或部署失败时停止后续步骤，按本文“失败处理”执行。

## 第三步：创建管理员

1. 部署成功后，打开供应方确认的 WebUI 地址 `/login`。
2. 指定所有者从新实例目录的受限文件 `credentials/webui-bootstrap-token` 领取引导密钥，输入页面，并自行设置管理员账号和密码。
3. 创建成功后退出并重新登录，确认可以进入管理页面。

密钥由供应方按实例配套提供；不要在命令行、Helm values、日志、工单或公共聊天中粘贴密钥。若页面已要求直接登录，先由供应方核实账号状态，不删除管理员或安全库文件重新认领。

## 完成确认

请与供应方共同记录：

- 运行镜像为本次 r6；“版本信息”的构建提交与本说明一致。
- 原 PVC UID、资源名称、内容根、访问地址和端口保留；未暴露 KTX 7878。
- 正确密钥可创建首个所有者，错误密钥和重复认领被拒绝；退出后可重登。
- 在维护窗口验证 Pod 重启后账号仍可登录，不再次认领。
- 原数据库连接、语义层、业务 Wiki、业务 Skill、权限和历史审计可正常使用。
- 原 MCP Token 的初始化、工具列表及一条允许查询正常；无 Token 访问和原禁止查询仍被拒绝。
- 备份存在且校验通过；同类测试环境完成原版本/PVC 恢复及再次升级验证。

详细项目按实例目录 `package/ACCEPTANCE.md` 和 `package/UPGRADE-RELEASE-CHECKLIST.md` 逐项记录。HTTP 与 HTTPS 分别验收，未执行项目填写待验。

## 失败处理

保留当前实例目录，记录报错的阶段、错误码、异常类型，以及 `.diagnostics/` 内脱敏诊断路径，交给供应方核对。不要手改脚本、校验文件、实例 ID、Secret 或删除状态目录绕过检查。

预检或备份失败且尚未开始 Helm 时，脚本会尝试恢复旧副本；仍需确认旧服务状态。Helm 开始后失败时，先检查当前镜像与运行状态，按交付实例目录的 `RECOVERY.md` 执行恢复。Helm 自动回滚不恢复 PVC 数据。

恢复旧备份会撤回升级后的管理员、业务修改和 Token 撤销等变化，应由恢复负责人核对后再开放访问。重试保留原实例目录和初始备份，继续使用该实例原密钥。

回传包 SHA256、前后镜像身份、资源 UID、Helm revision、时间和逐项验收结果；不回传密码、密钥、Cookie、完整 values、Secret 或 PVC 备份。
