## 2 执行升级预检

在正式升级使用的同一操作机、账号及 kubectl context 下执行：

```bash
umask 077
cd /opt/lucy-private/r6-instance
bash scripts/deploy.sh --dry-run
```

预期：命令退出码为 0，最后输出 JSON 中 `status` 为 `DRY_RUN`。出现错误、非零退出或输出不完整，均记为 FAIL，暂不部署；不要仅凭最后一行看起来正常判定通过。

该命令会读取目标集群、在旧 Pod 内运行只读身份探测并渲染候选资源，不创建 Secret、不导入镜像、不停止旧服务、不执行 Helm 升级。本地会使用临时文件，失败时可能生成脱敏诊断。它不会打印引导密钥。

以下项目由当前预检覆盖，客户记录命令结果，供应方按需复核详细项：

| 编号 | 检查项 | 通过标准 | 结果 / 证据 |
|---|---|---|---|
| P05 | 软件及实例绑定 | 包内校验、镜像元数据、实例 values、恢复说明及配置的 CA 文件校验通过 | 待验 |
| P06 | 操作机和集群资源 | kubectl/Helm 可用，当前 context 正确；原 release、Deployment、PVC 存在且状态符合要求，身份与配置一致 | 待验 |
| P07 | 账号状态与密钥 | 实际探测为 uninitialized；实例密钥格式及文件权限符合要求；同名 Bootstrap Secret 缺失或与本实例同值，引用的其他 Secret 存在且具有创建 Secret 权限 | 待验 |
| P08 | 节点与离线导入映射 | 当前实现识别的可调度目标节点均为 Ready、linux/amd64，节点到本机/SSH 的导入映射齐全 | 待验 |
| P09 | 渲染及旧内容兼容 | Helm lint 和资源渲染成功；原 PVC 管理方式、名称/规格、Deployment 选择器、数据挂载及 Service 名称检查通过；引导密钥挂载符合要求；供应方另行核对人工补丁漂移、旧语义类型和角色 AbsoluteDeny 冲突，见[供应方准备](供应方准备.md) | 待验 |

P05–P10 统一以完整 dry-run 通过为必要条件，P09 的旧内容兼容检查由供应方补充留证。dry-run 只证明当前检查范围通过；网络实际连通、证书信任和写操作能力仍需下面的现场确认。

本机空间可在实例目录只读检查：

```bash
df -h .
```

供应方结合实际 PVC 已用空间、归档开销和另存需要判断空间是否充足。不要仅因 `df` 命令成功就填写 PASS。

P12 的权限核对不等于镜像导入、卷挂载和备份已实际成功；它们在正式部署阶段执行。不要为了填写本检查单提前缩容或创建备份 Pod。

## 4 作出升级判断

每项填写 PASS、FAIL 或待验，并记录证据。确实不适用的子项由供应方注明原因，例如 HTTP 不适用证书检查；不能将整个访问检查项直接略过。

- **可以进入正式部署**：P01–P14 全部适用内容 PASS，dry-run 完整通过，供应方复核确认，并已到维护窗口。
- **暂不部署**：任一适用内容 FAIL 或待验。旧服务保持运行，按阶段、错误码及脱敏诊断处理后，重新检查。
