# r6 集成与部署入口

Lucy 2.0.0 / KTX 0.16.0 / Chart 0.2.6，linux/amd64。当前为升级验证候选，原生升级与恢复验收待完成。

本批次面向已有单副本 Kubernetes/K3s、仍无管理员的旧系统原地升级，保留原 release、Deployment、Service、PVC 和业务配置。其他场景由供应方单独确认，不套用无管理员认领流程。

软件包采用离线镜像归档。按实例 profile，在全部目标节点使用 K3s containerd 或 Kubernetes containerd 导入；正式部署入口自动执行导入。节点上的 `docker load` 不等于集群 containerd 已有镜像，不在客户现场重新构建。

供应方先提供完整的新实例目录和匹配该实例的私有附件。收到目录后，先按[检查单](升级前检查单.md)完成核对；在该目录执行：

```bash
bash scripts/deploy.sh --dry-run
```

完整预检、补充兼容检查和现场条件全部通过，由供应方复核后，在维护窗口单独执行：

```bash
bash scripts/deploy.sh
```

脚本会再次预检，导入候选镜像，停机备份整个 PVC，配置引导 Secret，执行 Helm 并检查镜像身份。不要跳过入口直接照旧版手册执行裸 `helm upgrade`，也不要把旧版 values 样例整体覆盖到当前系统。

部署后依次创建首个所有者、验证重登和持久性、核对原 MCP Token 与权限及业务，再记录[验收](验收说明.md)。失败使用实例目录中已填写的 `RECOVERY.md`；Helm 回滚不恢复 PVC。

HTTP 与 HTTPS 分别记录；HTTPS 使用实际 TLS/CA，不忽略证书错误。容器端口 5174/7879，对外端口沿用原 Service，7878 只作为 Pod 内上游，不对外暴露。
